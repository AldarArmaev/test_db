# Проверка хранилища Bothost

Отдельный диагностический HTTP-сервис, без зависимостей и Telegram-токенов.
Пользователь и путь данных совпадают с WashBook: UID/GID 1000:1000, /app/data.
Ошибка проверки не завершает процесс, поэтому консоль остаётся доступной.
Не открывает washbook.sqlite. Создаёт только собственную БД washbook-storage-probe.sqlite
и уникальный временный файл, который удаляет после проверки записи.

## Запуск на Bothost

1. Упакуйте содержимое этой папки в ZIP: Dockerfile должен быть в корне архива.
2. Создайте отдельное тестовое приложение из архива, выберите собственный Dockerfile.
3. Включите домен и укажите порт 8080. Не переносите секреты WashBook.
4. Переменные: PORT=8080 и DATA_DIR=/app/data (уже заданы в образе).
5. Запустите и откройте логи. Найдите строку STORAGE_PROBE.
6. ok:true во всех трёх checks означает успешную запись и открытие SQLite.
   EACCES/EPERM — права, EROFS — файловая система только для чтения.
7. При каждом запуске starts увеличивается. Запишите число, пересоздайте контейнер
   через повторный деплой и проверьте рост числа: это проверка сохранения данных.

Новое приложение получает отдельное хранилище. Успех здесь не доказывает исправность
хранилища существующего WashBook; ошибку его тома нужно проверять отдельно.
Если Bothost требует токен при создании приложения, используйте отдельного тестового
бота; сам сервис токен не использует. Не заменяйте работающий WashBook этим архивом.

Для поддержки безопасно передать строку STORAGE_PROBE: сервис не выводит окружение,
токены, содержимое БД или исходные сообщения исключений.

## Проверка автоматической подготовки прав

Docker запускает entrypoint.mjs от root. Скрипт меняет владельца /app/data
и только трёх собственных файлов SQLite, если они существуют. Затем сбрасывает
дополнительные группы и переключается на UID/GID 1000:1000 до запуска сервера.
Рекурсивного chown нет; базу WashBook скрипт не открывает и не меняет.
Если подготовка не удалась, сервер всё равно запускается от непривилегированного
пользователя для диагностики. Ошибка сброса привилегий завершает процесс.

На Bothost обновите тестовый бот из Git и смотрите логи:
- STORAGE_PREPARE ok:true — изменение владельца разрешено.
- STORAGE_PROBE uid:1000, gid:1000 и write/sqlite ok:true — полный успех.
- После пересоздания контейнера starts должен увеличиться.
- NOT_ROOT — платформа принудительно запускает непривилегированного пользователя.
- EPERM/EROFS/EACCES при подготовке — ограничение тома/контейнера; нужна поддержка.

Это проверка отдельного тестового тома, не разрешение запускать весь WashBook от root.

## Диагностика сети Telegram

После открытия HTTP-порта сервис один раз запускает проверки и пишет NETWORK_PROBE
в логи. Хранилище и счётчик SQLite продолжают проверяться как прежде.
Никакие Telegram-токены, значения окружения и тела HTTP-ответов не используются.
Публичный HTTP endpoint не раскрывает результаты диагностики.

Проверяются фиксированные адреса api.telegram.org, core.telegram.org и example.com:
- system_dns: системное разрешение имени и полученные IPv4/IPv6 адреса;
- https: отдельные HTTPS-запросы IPv4/IPv6 без следования редиректам;
- tcp_443: соединение с первым найденным адресом каждого семейства;
- tls: TLS к тому же IP с правильным SNI и проверкой сертификата;
- public_dns_ipv4: сравнение ответа DNS для api.telegram.org через 1.1.1.1 и 8.8.8.8.

Этапы ограничены таймаутами; сокеты закрываются. HTTP-сервис не ждёт завершения
проверок перед началом обслуживания. Результаты идут между NETWORK_PROBE_START и
NETWORK_PROBE_DONE. Ошибка публичного DNS сама по себе не доказывает недоступность
Telegram: провайдер может ограничивать запросы к сторонним DNS-серверам.
Успешный TCP и неуспешный TLS указывают на проблему после установления соединения;
таймаут Telegram при работающем example.com — на различие маршрутов/фильтрации.
Успех одной проверки не доказывает постоянную доступность или пригодность токена.

На Bothost обновите микробот из Git, запустите и подождите до минуты. Пришлите строки
NETWORK_PROBE. При необходимости повторить: node /opt/storage-probe/network-probe.mjs
Локальные тесты (без сети): node --test network-probe.test.mjs
