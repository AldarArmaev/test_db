# Проверка хранилища Bothost

Отдельный диагностический HTTP-сервис, без зависимостей и Telegram-токенов.
Пользователь и путь данных совпадают с WashBook: UID/GID 1000:1000, /app/data.
Ошибка проверки не завершает процесс, поэтому консоль остаётся доступной.
Не открывает washbook.sqlite. Создаёт только собственную БД washbook-storage-probe.sqlite
и уникальный временный файл, который удаляет после проверки записи.

## Запуск на Bothost

1. Упакуйте содержимое этой папки в ZIP: Dockerfile должен быть в корне архива.
2. Создайте отдельное тестовое приложение из архива, выберите собственный Dockerfile.
3. Включите домен и укажите порт 8080. Не переносите секреты WashBook.
4. Переменные: PORT=8080 и DATA_DIR=/app/data (уже заданы в образе).
5. Запустите и откройте логи. Найдите строку STORAGE_PROBE.
6. ok:true во всех трёх checks означает успешную запись и открытие SQLite.
   EACCES/EPERM — права, EROFS — файловая система только для чтения.
7. При каждом запуске starts увеличивается. Запишите число, пересоздайте контейнер
   через повторный деплой и проверьте рост числа: это проверка сохранения данных.

Новое приложение получает отдельное хранилище. Успех здесь не доказывает исправность
хранилища существующего WashBook; ошибку его тома нужно проверять отдельно.
Если Bothost требует токен при создании приложения, используйте отдельного тестового
бота; сам сервис токен не использует. Не заменяйте работающий WashBook этим архивом.

Для поддержки безопасно передать строку STORAGE_PROBE: сервис не выводит окружение,
токены, содержимое БД или исходные сообщения исключений.
